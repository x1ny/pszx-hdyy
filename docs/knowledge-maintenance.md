# 知识维护

## 根入口的收录条件

AGENTS 只承载全仓工作方式、通用约束、常用命令和通用任务导航。新增正文前同时判断：

1. 是否适用于多个无关领域，而非一个模块或某次迭代？
2. 是否是 Agent 开始相关工作前必须知道的非默认约定，而非目录树、依赖清单或代码现状复述？
3. 是否能用一条简短约束表达，而无需带上业务字段、流程或实现背景？

未同时满足时写入所属专题；仅仅“这条很重要、以后可能踩坑”不构成进入根文件的理由。业务过渡状态、功能完成记录、模块保存顺序、字段口径、旧入口清理清单不进入 AGENTS，也不换成根文件下的新表格或长段落。

新增业务专题通过 `summary` / `read_when` 与 `docs:list` 发现，不为每个模块在根文件增加一行导航。旧的“改动连同理由写回这里”已改为“写回所属当前文档”；方向性取舍再记录到 ADR。

## 归属

| 知识 | 完整正文归属 | 实现附近留下什么 |
| --- | --- | --- |
| 运行与渲染模型、依赖方向 | [代码结构](code-structure.md) | 必要的非显然约束 |
| API、类型导入、业务信封 | [API 契约](api-contract.md) | 类型推导或调用约束 |
| 角色是数据、权限点是代码、授权覆盖 | [授权](authorization.md) | 集中映射、测试与短注释 |
| 某个业务的状态机、保存顺序、兼容期 | 对应模块专题，如 [环节保存](segment-config.md) | 摘要与专题路径；避免重复整篇设计 |
| 环境和交付步骤 | [开发工作流](development-workflow.md) | 相关脚本错误信息与修复入口 |
| 为什么这样决定、重审条件 | [ADR](architecture-decisions.md) | 链向相应决策或当前契约 |
| 某次调研、实施结果或过去的限制 | 原研究/执行记录 | 不默认升级为通用规则 |
| 重复发生、需要多步判断的任务 | 少量有明确触发条件的 skill | skill 引用当前专题，不再抄一份规则 |

当前指南应让读者先看到现在的操作与边界，历史原因置于标记清楚的背景中。代码说明实际状态，采纳的决策说明预期状态；冲突时核对依据，不把偶然实现当成规则。改功能时只更新受影响的知识，不要求每次任务写经验总结。

## 发现与状态

纳入索引的文档使用 `status`、`summary`、`read_when` 三个 frontmatter 字段。状态可选：`current`（当前指导）、`reference`（按需背景或专项材料）、`historical`（过去记录）、`draft`（未采纳方案）。

- `bun run docs:list` 只列 current；`--query <关键词>` 对路径、摘要和阅读条件过滤。
- `--all` 额外显示已标记的其他状态，不表示读取全部交接资料。
- 未标记文档保留原位，不自动推断为 current；活动任务方案仍可由相应 skill 明确导航。
- 索引不输出正文、不联网，也不执行文档里的命令。旧原型与旧项目不再作为当前开发的默认参考。

## 防止再次堆积

`bun run docs:check` 检查根文件固定通用章节、禁止新增子章节、32 KiB 硬预算、CLAUDE 单行桥接、元数据和当前文档本地链接。10 KiB 为根文件软提醒，预算按 UTF-8 字节而非中文字符计数。根导航必须指向明确标为 current 的专题。

这项检查也作为 `scripts/docs-list.test.ts` 的仓库用例，自动进入现有 `bun run test`。改变根章节结构必须连同本规则、检查器及理由一起审阅；不能为某个新模块放宽检查器。

机械检查能发现结构扩张、超限与失效入口，不能可靠判断一个通用标题下的段落是否夹带业务细节。修改 AGENTS 的审阅必须同时回答：为什么需要常驻、为什么不能放专题、哪个无关领域同样需要它。不能把“检查通过”宣称为语义上永远不会再混入模块知识。

链接检查覆盖行内本地文件链接，跳过代码范例和外网；标题锚点需要在迁移时核对。CLAUDE 保留 `@AGENTS.md`，不再用 `@` 展开所有专题。实际宿主加载及 skill 调用仍需要独立验证。
