## 5. `docs:list` 的最小实现约定

### 5.1 文档自己声明用途

对首批完成校准、准备纳入发现入口的文档添加三个字段：

```yaml
---
status: current
summary: 管理端 CRUD 的数据接线、表单、筛选和视觉约定
read_when:
  - 新建管理端 CRUD 模块
  - 修改管理端表单、表格筛选或操作列
---
```

`status` 使用 `current`、`reference`、`historical`、`draft`：

- `current`：已采纳、可用于当前任务的指导。
- `reference`：决策理由、背景或由某个 skill 按需调用的专项材料。
- `historical`：过去的结果或经验，不能直接决定当前任务做法。
- `draft`：尚未采纳的建议和方案。

状态标记本身不证明内容正确。混合了当前与历史的文档，先整理开头与章节边界再加入默认索引。未加元数据的文件继续保留，不默认推断成 current，也不为补标签扫描修改全部历史资料。

首批候选：三个新专题，加现有 code-structure、crud-page-guide、database-migrations、user-management-design、authorization、h5-itinerary、h5-seat-map、seating-canvas、baidu-location-picker、windows-worktree-notes、Docker README。实际纳入以完成内容核对为准。

| `bun run docs:list --query h5` | 对路径、summary、read_when 做确定性的文本过滤；不调用模型，不读全文到输出 |
| `bun run docs:list --all` | 包括已标记的 reference/historical/draft，逐条显示状态；不是递归输出所有原型和历史内容 |
| `bun run docs:check` | 校验入口预算、CLAUDE 桥接、元数据与当前入口链接；错误返回非零 |

输出示例：

```text
docs/h5-itinerary.md [current]
  H5 当前页面范式、分享访问链路和开发入口
  何时读：修改 H5 页面、访问校验、移动样式或错误展示

docs/h5-seat-map.md [current]
  嘉宾座位定位图的展示、数据与布局约定
  何时读：修改 H5 座位定位图
```

实现保持轻量：只读 `docs` 下的 Markdown 元数据和 `docker/README.md`，显式跳过交接、原型、依赖与隐藏 worktree 目录；排序稳定、路径统一、无网络。只解析规定的元数据结构并给出错误文件位置，不引入知识库服务或全文索引框架。

`docs:check` 可作为同一脚本的检查模式。最低检查项：

1. 根 AGENTS 字节数违反现有硬预算时报错，超出软目标只提示；宿主外部指令导致的总预算问题由真实加载验收确认。
2. CLAUDE 去除换行空白后保持 `@AGENTS.md`，未额外导入专题全文。
3. 已选择进入索引的文档字段完整、状态合法、摘要和阅读条件非空。
4. 根入口及纳入的当前文档中的本地文件链接存在；普通代码文本和命令中的路径不当作 Markdown 链接扫描。指向拟建文件的入口只能在文件落地后启用。
5. 首版不写一个完整 Markdown 渲染器；关键标题锚点在迁移验收中逐个核对，外部链接不在离线检查中联网请求。

索引脚本加入 `scripts/tsconfig.json` 的 include（当前配置是显式文件列表）。为过滤 current/历史、缺失元数据、失效链接、中文及空格路径准备小型输入夹具，验证索引行为；无需为每段文案写镜像测试。

## 6. 如何实施而不丢知识

按依赖顺序分三步落地，均属于第一轮的知识入口提交范围：

**第一步：承接内容。** 建立三个专题，校准已有专题，记录本方案第 3 节的每个原段落最终去向。先让新入口的目标存在，再缩减根文件。属于历史的内容保留理由和时间，属于重复的内容只保留一个完整版本。

**第二步：入口与发现。** 增加元数据、索引及检查脚本；将 AGENTS 替换为校准后的候选正文，CLAUDE 桥接保持不变。一次检查全部当前链接，保留现有 skill 和 Intent 入口，不提前切换后续提交才会提供的命令。

**第三步：验证阅读效果。** 静态校验后执行下表的资料定位试验。先验证能找到正确规则，再在后续第一轮评估中进行真实实现任务的前后对照。

| 不提示文档名的任务描述 | 预期找到的知识 | 不能出现的结果 |
| --- | --- | --- |
| 给供应商列表增加一个筛选项 | CRUD 的筛选草稿、查询/刷新与 supplier 范式 | 直接套用即时查询；无差别加载全部专题 |
| 调整 H5 行程页面与手机号入口 | H5 当前分享路由、简化访问能力、独立 UI | 判断 H5 尚未接后端；误用管理端身份或 shadcn |
| 修改环节的人员和资源保存 | 增量意图、事务编排、两条写入顺序 | 把草稿改为完整目标名单覆盖 |
| 连接正在运行的开发数据库 | 开发脚本产生的连接配置 | 猜持久库地址或把连接串输出进报告 |
| 调整人工拖拽顺序 / 按姓名升序 | 前者进入排序 skill；后者按普通列排序处理 | 两类任务都强制加载排序方案 |
| 新增一个后台权限入口 | 权限专题、集中映射与接线测试 | 仅增加前端显隐 |

Codex 与 Claude Code 分别从仓库根的干净会话验证，记录宿主版本、实际读到的文件和遗漏规则。人工提示了具体路径的结果另标为“显式定位”，不计入自然发现成功。没有 Claude 运行环境时，该项保持待验收，不以目录存在替代测试。

静态验收包括：迁移表无遗漏、根预算满足、当前链接有效、CLAUDE 桥接正确、索引过滤与脚本类型检查通过。纯知识迁移不要求重跑整套业务测试；索引脚本执行自身必要检查，完整业务任务评估在相应阶段进行。

失败时按原因修订：找不到资料就改路标或 read_when；读到了仍遗漏就改正文组织或增加必要的根摘要；总是加载无关资料就收窄触发条件。不能统一用“多写一个 MUST”处理所有失败。

## 7. 后续维护规则

每次功能变更只回答三个问题：是否改变了已有约定，是否让某个入口过期，是否产生了值得复用的操作步骤。命中哪个，就更新相应当前文档或 skill；不要求每次任务写经验总结。

根文件只在全局边界、常用命令或高频任务入口改变时更新。新增一般专题写自己的 summary/read_when，通过 docs:list 发现；只有反复发生漏读的高风险主题才提升到根入口。这样限制入口增长，同时保留纠偏机制。

本方案依据此前已核验的 [Codex 指令发现机制](https://learn.chatgpt.com/docs/agent-configuration/agents-md)、[Claude Code 导入机制](https://code.claude.com/docs/en/memory)、[Vercel 文档发现实验](https://vercel.com/blog/agents-md-outperforms-skills-in-our-agent-evals)，以及 [agent-scripts 的文档目录实现](https://github.com/steipete/agent-scripts/blob/b05b1ed676bf6d6d1f3e1d3b72bc8ec7661c8d7b/scripts/docs-list.ts)。具体文件划分、元数据与验收任务是针对本仓库提出的方案，需要通过上述验证后采纳。
