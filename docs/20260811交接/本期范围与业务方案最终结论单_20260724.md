## 6. PRD候选回填文本

> 以下文本仅为主对话后续回填 PRD 的候选条款，不代表本分支已完成正式 PRD 更新。

### 6.1 产品定位与本期目标

活动运营平台定位为面向活动筹备、活动配置、人员管理、公众报名、资源记录与绑定、排位管理、议程配置和基础验收的智能活动运营平台。

本期建设目标为完成“Web 管理端基础能力 + 部分扩展闭环”的交付边界。Web 管理端基础能力为 P0，部分扩展闭环为 P1。完整平台级 PRD 可覆盖后续规划能力，但后续规划能力不纳入本期交付及验收范围。关联事项：C-003。

### 6.2 交付端范围

本期交付 Web 管理端和移动公众端 H5。Web 管理端承载项目管理、活动管理、活动工作空间、排位管理、邀请函管理、供应商管理、全量人员管理、系统管理、资源记录与绑定、议程配置等管理能力。移动公众端 H5 承载公众报名、报名结果、邀请函、活动行程、签到凭证、扫码获取嘉宾专属信息，以及本人用车、用餐、住宿安排查看。

移动执行端和移动指挥端为后续规划，不纳入本期交付及验收范围。关联事项：C-004、C-006。

### 6.3 Web 管理端基础能力

本期 Web 管理端 P0 能力包括项目管理、排位管理、邀请函管理、供应商管理、全量人员管理和系统管理。

项目管理包括项目汇总管理、历史项目、项目人员汇总、项目关联信息、活动管理、历史活动、活动人员汇总、活动关联信息、活动工作空间、环节配置管理和环节资源管理。排位管理包括场地模板管理和排位管理。系统管理包括用户管理、角色管理和权限管理。关联事项：C-003。

### 6.4 移动公众端与公众报名

本期建设移动公众端 H5。每场活动支持生成专属活动报名链接，后台可配置外部报名表单字段，并生成独立二维码或链接供外部渠道或公众号发布。

公众报名支持微信授权手机号，也支持手动填写手机号并完成验证。默认报名字段为姓名、手机号、单位、职务；证件类型和证件号码可配置但均为非必填。公众报名渠道、嘉宾名单和后台录入嘉宾信息均不强制实名，后台录入嘉宾手机号非必填，手机号不作为人员唯一校验依据。

报名成功后自动分配“普通观众”标签并同步至后台人员池。人员信息若根据姓名、手机号无法去重，则新增一条人员记录并保留。公众报名后形成每场活动的观众嘉宾名单，审核通过人员同步至对应活动人员库；后台录入受邀嘉宾也进入活动人员库。活动人员库记录人员来源，并作为排位和资源绑定的数据来源。

报名表单提交成功后状态为“已提交”；后台人员审核报名通过后状态变为“待核验”；到达现场扫码后状态变为“已核验”。公众报名观众嘉宾和后台录入受邀嘉宾均支持线下扫码获取嘉宾专属信息，现场工作人员线下查看信息后放行。本期系统不记录核验通过或核验不通过结果，不提供工作人员在线点击核验结果。关联事项：C-004、C-006。

### 6.5 供应商管理与历史报价存档

本期建设供应商基础资料管理和历史报价附件存档。历史报价记录以上传文件、文件名、上传时间、上传人、供应商和可选关联活动为基础信息，报价单字段不做统一结构化要求。同一供应商、同一活动下允许存在多条历史报价记录。

历史报价附件包括报价单、合同、沟通记录等。本期仅支持按供应商、上传时间、上传人、文件名、关联活动等基础信息检索。本期不建设价格比较、排名、评分、自动推荐、选定记录和比价结论，不纳入本期交付及验收范围。

历史报价附件使用独立权限点控制，普通活动运营人员不可见；上传、下载、删除或作废等动作需留痕。本期不做物理删除。关联事项：C-005。

### 6.6 资源记录与绑定

本期建设“资源记录与绑定”，不建设完整资源调度工作流程。资源记录与绑定采用“活动级资源台账 + 环节资源需求声明与关联 + 人员级服务信息展示”的三层模型。

活动级资源台账用于统一维护用车、用餐、住宿、物料、场地、供应商服务等资源记录。环节资源需求项用于在活动环节需要相关资源时声明需求状态、补充说明，并可按需关联活动级已有资源记录；不是所有环节都必须开启资源需求项。人员级服务信息展示用于向被绑定人员展示本人相关服务安排。

用车本期支持用车记录、车辆和司机信息、乘车人员绑定，并在移动公众端 H5 展示被绑定嘉宾本人的用车安排。司机或现场工作人员查看接送对象、司机接送确认、现场执行状态反馈、车辆定位、路线规划和自动派车不纳入本期交付及验收范围。

用餐本期支持基础用餐记录、人员绑定和移动公众端 H5 本人用餐安排查看；特殊用餐要求不纳入本期交付及验收范围。住宿本期支持入住酒店信息、人员绑定和移动公众端 H5 本人住宿信息查看；房型、入住离店时间、房间号、同住人、酒店入住确认和酒店端协同不纳入本期交付及验收范围。

物料、场地、供应商服务本期按基础记录和关联能力处理，不扩展为库存、领用归还、扫码盘点、供应商协同或履约评价闭环。关联事项：C-006、C-016。

### 6.7 排位管理

本期建设独立排位工作台。排位管理采用“场地功能图 + 环节排位图 + 排位方案”的三层模型。

场地功能图用于维护场地基础区域、功能结构、通道、固定设施和固定物理座位或点位底图。固定座位场馆可在场地功能图中维护基础物理座位信息，但场地功能图不直接承载具体环节排位结果。

环节排位图基于活动、场地和具体环节生成，用于选择本环节启用区域，并在启用区域内设置本环节实际使用的座位、桌位、站位、指定位置、位置顺序和重要等级。环节排位图支持区域聚焦和下钻排位。不同环节或不同时间段可基于同一场地生成不同排位图。

排位方案用于绑定人员并形成排位结果。排位方案按“活动 + 场地 + 环节/时间段 + 版本”管理。排位支持活动人员库人员预填、排位顺序规则辅助、人工绑定、调整、解除绑定、对调位置和批量顺序绑定。移除人员后的自动补齐为可选操作，由运营人员触发并确认，不默认自动执行。团体相邻本期采用规则辅助、区域排位和人工调整方式处理，不建设复杂自动最优算法。

排位状态集合包括未排位、排位中、已保存、待确认、已确认、退回修改、已导出、已作废。具体状态流转、触发条件和异常处理在后续“业务流程、状态与异常闭环”主题中细化。关联事项：C-006。

### 6.8 议程串并行与环节资源需求项

本期建设基础议程配置闭环。新增环节字段包括环节名称、环节类型、开始时间、结束时间、地点/空间备注、说明、是否开启环节人员管理、是否开启排位管理，以及是否开启具体资源需求项。

资源需求不是统一总开关，而是按具体资源项分别控制，例如用车需求、用餐需求、住宿需求、物料需求等。不是所有环节都需要资源需求标记，仅在当前环节确有资源需求时才开启对应需求项。环节资源需求项不是资源记录本身，而是环节对某类资源的配置任务。C-016 负责声明环节是否开启具体需求项、记录需求状态和补充说明，并统计配置完整性；C-006 负责维护实际资源记录、人员绑定、附件留档和移动公众端本人服务信息展示。配置完整性汇总应按具体资源需求项统计，而不是按资源大类统计。

议程图根据环节开始时间和结束时间自动绘制。时间连续展示为串行，时间重叠或有交集展示为并行，允许多个并行层。本期不支持拖拽排序，议程顺序调整通过编辑环节时间完成。

编辑环节后系统记录修改人、修改时间和历史版本。页面本期不展示历史版本列表，也不支持运营人员回滚。

本期业务冲突采用允许保存并提示的原则。冲突类型、提示文案、是否阻断、是否允许覆盖和配置进度计算在后续“业务流程、状态与异常闭环”主题中细化。关联事项：C-016、C-006。

### 6.9 议程画布导出

本期议程画布支持导出完整画布图，格式包括 PDF、PNG、JPEG。议程画布导出需受权限控制，失败后允许再次导出。导出权限点、敏感字段、水印、分页、分辨率、失败原因和导出日志字段在后续权限与异常主题中细化。关联事项：C-016。

### 6.10 本期不建设内容

以下能力不纳入本期交付及验收范围：

1. 移动执行端和移动指挥端。关联事项：C-004、C-006。
2. 工作人员端或司机端查看接送对象、接送确认和现场执行状态反馈。关联事项：C-006。
3. 采购比价、报价排名、评分、自动推荐、选定记录和比价结论。关联事项：C-005。
4. 完整资源调度中心，包括派单、执行回执、调度审批、现场状态回传和供应商协同。关联事项：C-006。
5. 物料库存管理、领用归还、损耗管理和扫码盘点。关联事项：C-006。
6. 特殊用餐要求、餐券核销、现场用餐确认和餐饮供应商履约。关联事项：C-006。
7. 房型、入住离店时间、房间号、同住人、酒店入住确认和酒店端协同。关联事项：C-006。
8. 复杂自动最优排位、智能冲突检测和自动推荐排位。关联事项：C-006。
9. 议程拖拽排序、跨层拖拽调整和复杂自动排程。关联事项：C-016。
10. 运营人员页面操作历史版本回滚。关联事项：C-016。

### 6.11 本期验收边界

本期验收以已确认的 P0/P1 范围为准。Web 管理端基础能力为 P0，扩展闭环为 P1。测试环境允许按本期边界分批补齐扩展闭环，但必须列举全部能力并注明已有、待补齐、分批计划和补齐顺序。

测试环境现状仅作为核验依据，不作为本期业务范围决策依据。后续规划能力不纳入本期交付及验收范围。详细权限、状态、异常、配置进度、导入导出失败处理、接口同步和测试环境缺口核验，移交对应派生继续处理。
