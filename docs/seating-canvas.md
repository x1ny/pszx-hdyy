# 区域与座位画布解耦

2026-09-08 用户逐项确认。外层区域表达相对位置和大小比例，内层座位表达排布；用户不必为了容纳更多座位返回外层扩大区域。

## 坐标与显示

- 每个区域有独立的座位坐标系，支持负坐标；新增、移动和模板生成均不使用区域尺寸限制座位。
- 外层区域移动、缩放只改变区域图形；多边形顶点仍随自身包围盒缩放，座位坐标不变。
- 内层编辑、人员入座、议程预览和导出只显示座位与区域名称，不画外层区域形状。
- 外层总览仍展示区域分布及位置数量；本次不增加舞台、入口等标注。

## 模板与视角

- 模板保持整体替换，沿用替换提示和撤销；零星补位使用“点放位置”。
- 剧场座位中心横向间距 48、排距 64；过道多留一个横向间距。圆桌按相邻座位中心距离至少 48 扩大半径，桌子包围盒间距 96；秀场两侧相距 160。这些是画布单位，不代表现实长度。
- 首次进入按全部座位的实际范围居中缩放并留白；空画布以原点为中心。导入模板后重新适配。
- 平时增删、拖动座位保持视角；“适配”始终重新显示全部内容。缩放可低于旧的 0.15 倍，避免大布局首次滚轮缩放时突然跳近。
- 保留框选，增加“平移”工具；空格和鼠标中键也能临时平移。平移不修改座位或选择。
- 返回外层再进入同一区域，在当前编辑会话内恢复缩放和平移；退出整个编辑器或刷新后重新适配。视角不写进画布，也不触发保存。

## 数量与导出

- 场地库、活动空间、环节方案及团体批量选座不设固定座位数量上限；重复标识、重复编号及跨区域引用等语义校验仍保留。
- PostgreSQL 插入和长 ID 列表按 1,000 项分批执行，仍在原事务内。这是每条 SQL 的参数控制，不是座位总数限制。
- JPG 保持整图，超过位图尺寸预算时自动降低输出比例，不再因文字过小拒绝导出；另提供 SVG 矢量图，可放大查看。区域名称、座位状态和图例继续显示。
- 不承诺任意数量都能即时处理：浏览器绘制、JSON 请求和数据库仍消耗实际内存和时间；不以另一处隐藏数量门槛替代原来的 5,000 上限。

## 历史数据

保留 `schemaVersion: 1`，无需数据库迁移。旧座位坐标原样读取，不自动重排、重编号或保存；座位标识、人员绑定及已确认方案的状态不因本次升级改变。活动空间与环节方案仍保持既有快照隔离，修改上游不会自动同步已有方案。

## 验证重点

常规测试数据最多 1,000 个座位，避免把大规模压力测试放进每次测试运行。几何测试覆盖越界、负坐标、成组选中后的等量移动、撤销、外层缩放不动座位及模板间距；视角测试覆盖内容变化不跳动、极小比例缩放及会话恢复；导出测试覆盖负坐标、无区域框和完整矢量内容。服务端测试覆盖语义校验和 SQL 参数数目。

本次曾在临时数据库一次性使用 60×60 的外层区域保存并读取 10,001 个座位，完成活动空间导入、方案创建、整批移除、新模板替换和全量编号更新；另检查已有已确认方案及分配保持不变。这份大样本不纳入常规测试，也不作为持续压测要求。
