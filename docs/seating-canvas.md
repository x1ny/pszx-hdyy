# 区域与座位画布解耦

2026-09-08 用户逐项确认。外层区域表达相对位置和大小比例，内层座位表达排布；用户不必为了容纳更多座位返回外层扩大区域。

## 坐标与显示

### 业务区域与座席分区

2026-09-16 确认。场地平面图中的一个视觉整体可以由多个座席分区组成：业务区域是环节选择、统计和确认的单位，分区是独立绘制座位、进入排位画布和人员落座的单位。模型固定为两层，不支持任意嵌套。

- 场地编辑器用“归入新区域”把多个 `kind: "seating"` 分区归入一个业务区域；业务区域没有可绘制形状、不能直接有座位。解散业务区域只移除归属，保留分区、座位和排。
- 环节选择只列出独立座席区和业务区域，不列出已归属的分区。业务区域容量汇总当前启用分区的容量；停用分区不会进入新方案。
- 从业务区域创建的方案保留一个分区快照和各分区的独立座位坐标、显式排和稳定标识。方案先显示分区总览，再进入单个分区的画布；确认、人员统计、导出仍属于同一方案。
- 普通排和散座在分区内座号唯一；桌席以桌为查重范围，同桌内唯一、跨桌可重复。组合方案中的存储与展示前缀为“分区名 · 座号”，避免人员分配、H5 和导出发生歧义；单分区的旧方案保持原座号。
- 场地库、活动空间与方案均为既有快照边界：场地库重新分组不自动改活动空间，活动空间重组不自动改已有方案。

- 每个区域有独立的座位坐标系，支持负坐标；新增、移动和模板生成均不使用区域尺寸限制座位。
- 外层区域移动、缩放只改变区域图形；多边形顶点仍随自身包围盒缩放，座位坐标不变。
- 外层区域形状可绕自身中心旋转，区域名称和状态文字跟随同角度旋转；角度保存在 `shape.rotation`（SVG 坐标系下正数为顺时针）；历史画布缺少该字段时按 `0°` 读取。多个矩形区域可分别移动、旋转，近似表现看台或秀场的弧形分区，不新增弧线区域类型。
- 只有 `kind: "seating"` 的座席区可以进入二级排位；功能区、签到区和物料区仅展示区域名称与几何，不显示座位状态或“进入排位”入口。
- 内层编辑、人员入座、议程预览和导出只显示座位与区域名称，不画外层区域形状。
- 外层总览仍展示区域分布及位置数量；本次不增加舞台、入口等标注。

## 模板与视角

- 模板保持整体替换，沿用替换提示和撤销；零星补位使用“点放位置”。
- 剧场座位中心横向间距 48、排距 64；过道多留一个横向间距。圆桌按相邻座位中心距离至少 48 扩大半径，桌子包围盒间距 96；秀场两侧相距 160。这些是画布单位，不代表现实长度。
- 首次进入按全部座位的实际范围居中缩放并留白；空画布以原点为中心。导入模板后重新适配。
- 平时增删、拖动座位保持视角；“适配”始终重新显示全部内容。缩放可低于旧的 0.15 倍，避免大布局首次滚轮缩放时突然跳近。
- 保留框选，增加“平移”工具；空格和鼠标中键也能临时平移。平移不修改座位或选择。
- 返回外层再进入同一区域，在当前编辑会话内恢复缩放和平移；退出整个编辑器或刷新后重新适配。视角不写进画布，也不触发保存。

## 显式排与参数编辑

2026-09-15 按用户需求增加排对象，决策见 [ADR](architecture-decisions.md#座位编辑器显式排)。`CanvasDoc.rows` 为可选有序数组，每排有稳定 ID、区域 ID、名称、按排内顺序保存的 `seatIds`，以及起点（环形排为圆心）、方向、间距和过道参数。名称不参与排序，画布位置不推导归属；列表上下移调整排顺序，单座自由拖动不改排关系。

- “画排”工具支持拖出直排的方向和长度，或从圆心向外拖出环形排；数量按间距计算并预览。也可按参数在当前视野中心创建。选择列表中的排后，可以整体拖动，也可编辑数量、间距、角度、形状和过道频率。
- 排参数修改后立即写入文档；无效的中间输入（空值、非整数数量、非正间距或空名称）只留在输入框，恢复有效值才写入。每次有效修改或一次拖动为一个撤销步骤。增减数量从排尾开始，保留存活座位 ID、编号、种类和等级；直排只改数量时保留已有座位的自由调整。改间距、方向、形状或过道会按参数重新排布；环形排增减数量也重排。
- 整排移动同时更新参数起点；单座删除同步移出排清单。删除区域、整排和导入替换模板同步清理关联。面板删除整排有确认，选中排后 Delete 可直接删除并撤销；减座显示移除数量。Escape 取消正在绘制的排。
- 模板共用排坐标生成器：剧场每行一排；秀场左右独立成排，顺序由模板明确写入；宴会每桌一条环形排。模板保留原有编号规则，新增座位沿用生成规则，普通排重号追加后缀，桌席按桌重新从 `1号` 开始，跨桌不追加 `-2`；已有座位不会自动重编号。改排名称也不会重编号。
- 排信息随现有画布 blob 保存，不新增数据库表。活动空间复制画布时沿用排信息，创建环节方案时只保留目标区域的排；已有方案与上游继续快照隔离。入座模式不开放画排或排参数修改。
- 老画布没有 `rows` 时原样读取，座位视为未归排，不解析标签或坐标补排。新画布解析拒绝重复归属、跨区座位和失效引用。旧版编辑器会丢弃新增排信息，因此带排文档应使用新版编辑器维护。
- H5 团体座位范围读取 `rows[].seatIds` 的显式顺序，按排内连续数字压缩为范围；`aisleEvery` 只影响画布留白，不切断连续座号。没有 `rows` 的历史画布退回逐个座位号，不从标签或坐标猜排。

## 桌：圆桌与方桌

2026-09-16 按用户需求增加，决策见 [ADR](architecture-decisions.md#桌是排的两种-shape不是新的顶层概念)。桌不是新的顶层对象，是排的两种 `shape`：`"circle"`（圆桌，沿用既有环形排）和新增的 `"rect"`（方桌）。两者共同点：画布上会画出实体桌面图形（描边+桌名文字），`shape: "line"` 的普通排不画家具，行为不变。

- 方桌新增 `sides: { top, right, bottom, left }`，四侧各自的座位数，允许为 0；两侧长桌就是上下两侧填 0 的特例，四侧围坐则四个都填。座位顺时针从上边左端开始编号（上→右→下→左），保证 `seatIds` 是一条连续顺序，跟圆桌的编号习惯一致，H5 范围合并直接复用，不用额外处理。
- 桌面尺寸不落库：圆桌半径由 `spacing`/座位数派生（`rowRadius`），方桌宽高由 `spacing`/四侧座位数派生（各侧以自己的座数独立居中，宽高取两侧跨度的较大值兜底），渲染和导出都调用同一个 `tableGeometry`（`apps/web` 的 `core/rows.ts`），只有一份几何来源。座位与桌面之间留一条随座距缩放的间隙（`spacing × 0.35`，下限 16），避免小桌子被固定间距撑爆。
- 桌子的座位数由用户直接配置四侧人数自动生成，**不提供手画桌面座位的工具**：`rowParamsFromDrag` 对方桌原样返回参数，画排工具的拖拽对方桌退化成落点，创建入口只有点一下（沿用 `rowDefaults`）和"按参数创建"。圆桌沿用已有的画排/拖拽创建。
- 桌面图形只用于渲染和导出（编辑器画布、JPG/SVG 导出），不参与排座逻辑、不影响座位分配——跟排的位置不推导归属是同一个原则。移动整桌（选中排内全部座位一起拖）会带着桌面图形一起走，几何来源是同一个 `row.x/row.y`，不需要额外同步。
- **桌的座位不能单独拖动**：普通排允许单座自由移动（上面"显式排与参数编辑"一节），但桌上的座位是围着一张实体桌子摆的，单独挪一个会让座位飞离桌面。拖动命中桌上任一座位、或命中桌面本体的空档（`interaction.ts` 的 `hitTable`，按圆桌半径/方桌矩形做几何命中），都会把拖动目标替换成整桌的 `seatIds`，不取当前选区，也不允许只拖其中一个；直排的座位不受影响，行为不变。
- H5 座位图会画出桌面外框（见 [H5 座位定位图](h5-seat-map.md)），管理端负责生成合法的 `sides`；旧文档没有 `rect` shape 或 `sides` 字段时原样读取，不受影响。
- 默认命名和编号都不重复"桌"这件事——桌名已经画在桌面中央：新建时不设名称按"第 N 桌"（区别于直排的"第 N 排"，`addRow` 按 shape 分两套计数）；没有 `numbering` 时座位按桌内顺序编"1 号、2 号…"，不带桌号前缀（`rows.ts` 的 `defaultNumbering`）；模板对话框"本桌座号"编号规则同理，不再是"1桌2号"这种带桌号的格式。方桌桌面画圆角矩形；桌面描边和空座是同一套画法（卡片底色 + 24% 透明度主题蓝描边），不是实心蓝块，也不用灰色。

## 数量与导出

- 场地库、活动空间、环节方案及团体批量选座不设固定座位数量上限；重复标识、查重范围内重复编号及跨区域引用等语义校验仍保留。
- PostgreSQL 插入和长 ID 列表按 1,000 项分批执行，仍在原事务内。这是每条 SQL 的参数控制，不是座位总数限制。
- JPG 保持整图，超过位图尺寸预算时自动降低输出比例，不再因文字过小拒绝导出；另提供 SVG 矢量图，可放大查看。区域名称、座位状态和图例继续显示。
- 不承诺任意数量都能即时处理：浏览器绘制、JSON 请求和数据库仍消耗实际内存和时间；不以另一处隐藏数量门槛替代原来的 5,000 上限。

## 历史数据

保留 `schemaVersion: 1`，无需数据库迁移。旧座位坐标原样读取，不自动重排、重编号或保存；座位标识、人员绑定及已确认方案的状态不因本次升级改变。活动空间与环节方案仍保持既有快照隔离，修改上游不会自动同步已有方案。

## 验证重点

常规测试数据最多 1,000 个座位，避免把大规模压力测试放进每次测试运行。几何测试覆盖越界、负坐标、成组选中后的等量移动、撤销、外层缩放不动座位及模板间距；视角测试覆盖内容变化不跳动、极小比例缩放及会话恢复；导出测试覆盖负坐标、无区域框和完整矢量内容。服务端测试覆盖语义校验和 SQL 参数数目。

本次曾在临时数据库一次性使用 60×60 的外层区域保存并读取 10,001 个座位，完成活动空间导入、方案创建、整批移除、新模板替换和全量编号更新；另检查已有已确认方案及分配保持不变。这份大样本不纳入常规测试，也不作为持续压测要求。
